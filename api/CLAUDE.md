# api/

Every change in `api/` is **High** tier: Ben approves and the-enforcer passes.

| File | What it does | Auth |
|---|---|---|
| `chat.js` | Text assistant for two callers. The live demo (`demo.html`) sends its own prompt, checked against the demo template. A website preview's "Ask" box (`/preview/<slug>`, Nov 12) sends only `{preview, chat}`: the server reads that preview's profile (`profileFor` in `preview.js`) and writes the prompt itself, from the facts the page shows plus a never-answer list by kind of business (firearms: who may buy goes to the owner; a reply that still says who may buy, or names a buying age, is swapped for a hand-off on the server). Returns one JSON reply; GET reports whether AI is on | Public; same-origin check and per-IP limit (both callers share it) |
| `lead.js` | Saves a walkthrough request (contact form or walkthrough chat) to Supabase `leads` with the server key (`SUPABASE_SECRET_KEY`, from the Supabase integration); 3 per IP per hour, 6 a day, plus the Vercel firewall rule on `/api/lead`. The browser can no longer write the table. Qualifies it first (Nov 13, `../qualify.js`, the same file the page loads): the message starts with `Fit: fit`, `Fit: check (...)` or `Fit: not a fit (...)` and an `Answers:` line, and the reply carries `fit`. After a save of a fit or a check it starts the Event runner and tells The Engine (`POST ops.plainlineops.com/api/check {push: "inquiries"}`, 3 s, the word only), which sends Ben's phone alert; a request that is not a fit does neither. The seller page's answers are saved as they are | Public; same-origin check and per-IP limit |
| `studio-scan.js` | Studio: fetches a business's website server-side and returns its pages. Public addresses only: the connection's own DNS lookup is checked (`safeLookup`), so there's no second lookup to rebind | `x-studio-key` header (Ben only) |
| `studio-build.js` | Studio: asks Claude to build a client site from a scan | `x-studio-key` header (Ben only) |
| `studio-profile.js` | Studio engine path: asks Claude for a site profile as structured output (`output_config.format` with the `PROFILE` schema, every object closed and every field required, as The Engine's deck does; Sonnet 5.5 refuses forced tool use with a 400), then sanitizes it and keeps only photos and links from the scan; streams a heartbeat, last line is the JSON. `plan()` is shared with `preview.js` | `x-studio-key` header (Ben only) |
| `preview.js` | The Engine's free website previews: POST (from ops.plainlineops.com only) scans an approved lead's site and saves a Studio profile on the lead; GET `/preview/<slug>` serves it as a labeled, noindex concept page for 30 days, with a live "Ask" chat box (`chat.js`). `profileFor(slug)` is shared with `chat.js` | POST: the rep's Supabase token (row-level security, 2-step); GET: public, unguessable slug |
| `_studio.js` | Shared Studio helpers (`authorized`, `body`). Files starting with `_` aren't routes on Vercel. | — |
| `_fire.js` | `fireEvent(kind)`: starts the Event runner (Claude Code scheduled task trig_01QPPFmh4MwZEEjbd367YqaB, jarvis-app routines `events.md`) right after `lead.js` saves a request, so the booking-link reply goes out in minutes. Sends the kind word only; off until `EVENT_FIRE_TOKEN` is set; one fire per 2 minutes and 6 a day per instance; a failure is logged and dropped | — |
| `_errtype.js` | What to log when Anthropic returns an error: the error type plus a safe hint (a fixed phrase such as "credit balance too low", or the request field the API names, plus which allow-listed words such as "schema" or "workspace" the message mentions), never the body or its message (they can quote visitor or client-site text) | — |

Conventions every endpoint keeps:
- 405 for the wrong method, 400 for bad input, 401 for a wrong Studio key, 403 for a wrong origin on the public endpoints, 422 when a scan can't read a site, 429 when rate-limited, 501 when an env var is missing (`ANTHROPIC_API_KEY`, `STUDIO_KEY`), 502 when Claude or an upstream call fails.
- The demo keeps working without AI: 501 and 429 switch it to built-in replies for the rest of the visit; a 502 or network error falls back for that one reply (`demo.html`, the `/api/chat` call). The preview's Ask box does the same with one fixed answer (the shop's phone and the request form), in `studio-engine.js`.
- Haiku 5.5 thinks before it answers, and the thinking counts toward `max_tokens`: keep room for it (`chat.js` asks for 1024 with `output_config.effort` "low"). `ANTHROPIC_MODEL` must be a model that takes `effort` (Haiku 5.5 or newer).
- Models come from env: `ANTHROPIC_MODEL` for the public demo (default `claude-haiku-5-5`; keep it Haiku-class) and `STUDIO_MODEL` for Studio builds (default `claude-sonnet-5-5`).
- Never log or echo keys or full visitor messages. Compare secrets with `crypto.timingSafeEqual` (see `_studio.js`).
- The per-IP rate limit lives per warm instance, so it's soft. The real cap is the spend limit on the API key.
